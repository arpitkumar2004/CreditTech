# CONSTITUTION FOR AI-GENERATED MID-SEM PRESENTATION

## CreditTech — An Alternative Credit Decision-Support Platform for Rural India

> **Purpose:** This constitution defines the mandatory rules that an AI presentation-generation system must follow when creating the 16-slide Mid-Semester academic presentation for the CreditTech project. It governs **content, structure, visual hierarchy, UI/UX, typography, diagrams, charts, imagery, citations, academic rigor, consistency, and presentation quality**.
>
> The AI must treat this constitution as a **strict design and content specification**, not as optional recommendations.

---

# 0. CORE PRESENTATION IDENTITY

### Presentation Type

**Academic Mid-Semester Project / Thesis Presentation**

### Project

**CreditTech: An Alternative Credit Decision-Support Platform for Rural India**

### Primary Objective

The presentation must communicate:

> **Why the problem exists → who is affected → how the existing system fails → what CreditTech proposes → how the system is architected → what data and technologies enable it → how users interact with it → how governance is handled → how the pilot will be executed → what resources are required → what literature and evidence support the approach.**

The presentation is **not** a product pitch deck, startup investor deck, marketing presentation, or technical documentation.

It must feel like a:

> **high-quality engineering/research presentation with the visual polish of a premium SaaS product.**

---

# 1. MASTER DESIGN PHILOSOPHY

The entire PPT must follow these principles:

### 1.1 Academic First

Every visual and content decision must support academic communication.

The presentation must demonstrate:

* problem understanding
* literature grounding
* system thinking
* technical feasibility
* institutional understanding
* data understanding
* governance awareness
* implementation planning
* pilot design
* resource planning

Do **not** sacrifice academic substance merely to make the slides aesthetically attractive.

---

### 1.2 Minimal but Information-Dense

The presentation should be:

> **Minimal in visual noise, dense in meaningful information.**

Avoid:

* giant decorative headings
* excessive empty space
* unnecessary icons
* generic illustrations
* decorative gradients
* excessive rounded cards
* paragraphs
* stock-photo-heavy slides
* meaningless infographics

Every major visual element must communicate information.

---

### 1.3 One Slide = One Argument

Every slide must answer one primary question.

For example:

* Slide 3 → **Why is intervention needed?**
* Slide 5 → **Why does the existing system fail thin-file borrowers?**
* Slide 6 → **What changes in the proposed system?**
* Slide 7 → **How is the system technically structured?**
* Slide 13 → **How is the system governed?**

Do not allow one slide to simultaneously become:

> problem + architecture + technology + results + conclusion.

---

### 1.4 Visual Storytelling

The presentation should visually progress:

**Context → Problem → Existing System → Gap → Proposed System → Architecture → Data → Technology → Integration → Modules → User Journey → Governance → Pilot → Resources → Evidence**

The audience should understand the system even before reading every sentence.

# 13. CONTENT DENSITY

The AI must follow the:

# **3–5–7 Rule**

* approximately 3–5 major content groups per slide
* approximately 3–7 lines of meaningful text per content group

> **Never make the audience read a report on the slide.**

> There are a lot of different problems that are faced by people in rural areas because they don't have enough data available with the banks.

# 16. NUMBERS AND STATISTICS

All numbers must have:

* clear unit
* time period where applicable
* population/context
* source

> **140M+**

# 17. CLAIM PRECISION

The AI must distinguish between:

### Established fact

> RBI's Account Aggregator framework enables consent-based financial data sharing.

### Project implementation

> CreditTech implements a consent workflow designed around purpose limitation.

### Hypothesis

> Utility-payment regularity may provide an additional repayment signal.

### Simulation

> The modelled portfolio economics indicate...

### Future capability

> Planned integration with live AA infrastructure...

Never present a:

> future feature

as:

> an implemented feature.

---

# 18. ACADEMIC EVIDENCE RULE

Every important claim should be supported by one of:

### A. Literature evidence

A published paper/report.

### B. Institutional evidence

RBI, SIDBI, World Bank, NAFIS, Findex, etc.

### C. Project evidence

Actual CreditTech experiment, architecture, prototype, benchmark, or test.

### D. Explicit hypothesis

If evidence does not yet exist, label it as a hypothesis.

3–5 major content blocks.
